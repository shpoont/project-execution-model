# Contributing to PEM

Start with the [project agreement](PROJECT.md) and the
[current work and agreements](docs/README.md#current-work-and-agreements).
The README introduces the model to readers; these records explain work on the
repository. Follow applicable local instructions as well.

## Prepare a Focused Change

Identify the accepted agreement in the issue or pull request and link to it
from the other record. It states the increment's purpose, scope, approach,
acceptance checks and unresolved questions. A proposal or comment changes
that agreement only when accepted. Agree the scope before editing. Use a branch named
`proposal/<issue-number>-<short-topic>` and link the proposal to its issue.

Keep a complete baseline and the material needed to assess the change. Drafts,
sample passages and readable comparisons help people review an approach before
adopting it. They belong with the proposal rather than in a competing copy of
the published model. Reuse existing records and evidence when they still apply.

## Review Meaning and Reading

Content checks establish whether the proposal meets its agreement. Editorial
review establishes how clearly the intended meaning is communicated. For a
substantial document revision, use the agreed review plan, including independent
meaning preservation and fresh reader assessment. Keep the complete sources
and necessary images available to those reviews.

Record the versions actually reviewed, findings, corrections and remaining
limits in the pull request. A later edit needs the affected checks repeated;
it does not automatically inherit an earlier verdict. Separate observed results
from interpretations and hypothetical applications from evidence of actual use.

The [checks guide](tests/README.md) describes source, link, visual and release
checks. The [evidence guide](evidence/README.md) explains how to retain useful
results without copying private histories into the repository.

## Keep the Sources Connected

Edit the canonical [model](deliverables/project-execution-model.md) and its
[PNG assets](deliverables/assets/) directly. The editable overview
source is in [src](src/README.md). Keep references, examples and images aligned
with an accepted change. Preserve earlier decisions and record why a lasting
decision changes; release summaries belong in the changelog.

Repository changes must keep the model's guidance distinct from maintainer
instructions. Do not copy an upstream starter's model wording over the accepted
PEM agreement. Combine project records when that makes the work easier to follow.

## Complete and Hand Over

Before pausing or completing work, leave the issue or pull request clear about
what changed, what was checked, unresolved questions and the next useful action.
The maintainer accepts adoption and authorizes any merge or release. Follow
the [delivery guide](docs/delivery.md) and applicable local publication procedures.
